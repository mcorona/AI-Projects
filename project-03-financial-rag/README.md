# Financial RAG, Measured

## 📊 Project Overview

A retrieval-augmented QA system over 57,638 financial forum documents, built
to answer a question most RAG projects skip: **does any of this actually
work, and how would you know?**

Nearly every RAG tutorial ends with a screenshot of a plausible-looking
answer. That is not evidence. This project is built on a benchmark with
human relevance judgments, so every claim in it is measured against ground
truth rather than eyeballed — nine retrieval configurations scored against
648 human-judged queries, and four generation conditions scored by an LLM
judge that is itself calibrated before it is trusted.

**Dataset:** [FiQA-2018](https://sites.google.com/view/fiqa/) as distributed
in [BEIR](https://github.com/beir-cellar/beir) — 57,638 financial forum
answers (StackExchange / Reddit personal finance) and 648 test questions
with 1,706 human relevance judgments. Chosen because it is a *published*
benchmark: the numbers below can be checked against the literature instead
of existing in a vacuum.

## 📈 Results — Retrieval

FiQA-2018 test split, 648 queries, 57,638 documents.

| Configuration | nDCG@10 | Recall@10 | Recall@100 |
|---|---|---|---|
| Random (floor) | 0.0000 | 0.0000 | 0.0006 |
| BM25 (lexical baseline) | 0.2374 | 0.3009 | 0.5091 |
| BM25 + ms-marco reranker | 0.3239 | 0.3801 | 0.5091 |
| Dense — bge reranker on top | 0.3540 | 0.4392 | 0.7415 |
| Hybrid — RRF(BM25, bge) | 0.3588 | 0.4359 | 0.7184 |
| Dense — all-MiniLM-L6-v2 | 0.3687 | 0.4413 | 0.7061 |
| Hybrid + ms-marco reranker | 0.3743 | 0.4530 | 0.7184 |
| Dense + ms-marco reranker | 0.3851 | 0.4707 | 0.7415 |
| **Dense — bge-base-en-v1.5** | **0.4062** | **0.4814** | **0.7415** |

**Headline finding: the two components the standard RAG recipe recommends —
hybrid RRF fusion and cross-encoder reranking — both make the best retriever
*worse*.** Fusion costs 4.7 nDCG points (p < 0.0001), the MS MARCO reranker
costs 2.1 (p = 0.015), and the BGE reranker costs 5.2 (p < 0.0001). The
winner is a plain dense retriever with nothing bolted on top.

The reranker is not miswired. Applied to a *weak* first stage it does
exactly what reranking is famous for — BM25 goes from 0.2374 to 0.3239, a
**36% relative gain**. It simply has a quality ceiling below the dense
retriever on financial text, so adding it on top sorts good results into a
worse order.

This is the same failure mode as [Project 1](../project-01-customer-feedback-nlp/),
where an off-the-shelf DistilBERT sentiment model scored *below* a
rule-based baseline on financial text. General-purpose components transfer
badly to this domain, and measuring them against the thing they are
supposed to improve is the only way to find out.

### The implementation is validated, not just plausible

A broken retrieval harness still produces plausible-looking numbers. BEIR
publishes results for two of these configurations on this exact split:

| Configuration | This repo | Published BEIR | Difference |
|---|---|---|---|
| BM25 | 0.2374 | 0.236 | +0.0014 |
| bge-base-en-v1.5 | 0.4062 | 0.406 | +0.0002 |

### Are the gaps real?

Paired bootstrap over the 648 queries, 10,000 resamples
(`src/evaluation/significance.py`):

| Comparison | Δ nDCG@10 | 95% CI | p |
|---|---|---|---|
| Dense (bge) vs BM25 | +0.1689 | [+0.1438, +0.1936] | <0.0001 |
| Dense (bge) vs Dense (MiniLM) | +0.0376 | [+0.0193, +0.0560] | <0.0001 |
| Hybrid RRF vs Dense (bge) | **−0.0474** | [−0.0673, −0.0277] | <0.0001 |
| Dense + ms-marco rerank vs Dense | **−0.0212** | [−0.0380, −0.0043] | 0.0146 |
| Dense + bge rerank vs Dense | **−0.0523** | [−0.0718, −0.0330] | <0.0001 |
| BM25 + rerank vs BM25 | +0.0865 | [+0.0684, +0.1047] | <0.0001 |

648 queries cannot resolve every gap. The narrowest result here
(reranking costs 2.1 points, p = 0.015) is real but is the one a different
sample could plausibly soften; the rest are not close calls.

## 📈 Results — Answer Generation

150 FiQA test questions, four conditions, answers generated by
`claude-opus-5` via the Batches API.

The conditions isolate one variable at a time. `rag_bm25` and `rag_dense`
differ *only* in which retriever supplied the passages — a 17-point nDCG
gap upstream — which makes this the experiment that asks whether better
retrieval actually produces better answers.

### The checks that need no judge

These are measured against the human relevance judgments and a parser. No
model opinion is involved:

| Condition | Retriever nDCG@10 | Abstained | Citation precision | Invalid citations |
|---|---|---|---|---|
| No retrieval (closed book) | — | — | — | — |
| RAG — BM25 passages | 0.2374 | 40.7% | 0.199 | 0.000 |
| RAG — bge-base passages | 0.4062 | 19.3% | 0.303 | 0.000 |
| Oracle — gold passages | (ceiling) | 15.3% | 1.000 | 0.000 |

**Abstention tracks retrieval quality exactly.** Given BM25's weaker
passages the system declines to answer 40.7% of the time; given the better
retriever, 19.3%. That is the behaviour you want and almost never see
measured — the failure mode of a bad RAG system is not silence, it is a
confident answer wearing citations.

**Citation precision** — the share of cited passages that human annotators
actually marked relevant — moves the same way: 0.199 → 0.303 → 1.000. The
oracle's 1.000 is a pipeline check rather than a result: by construction
every oracle passage is gold, so anything below 1.0 would have meant a bug
in the context builder or the citation parser.

**Not one answer in 600 cited a passage number that did not exist.**

**The benchmark's own ceiling:** even handed the gold passages, the system
abstains 15.3% of the time. In roughly one case in seven, the documents a
human marked "relevant" do not actually contain an answer to the question.
That bounds every number in this table and is a property of FiQA, not of
the system.

## 🛠️ Tech Stack

| Component | Tool | Reason |
|---|---|---|
| **Lexical retrieval** | rank-bm25 (BEIR k1/b defaults) | The baseline a dense retriever must beat |
| **Dense retrieval** | sentence-transformers (bge-base, MiniLM) | Bi-encoder semantic search |
| **Reranking** | Cross-encoders (ms-marco, bge-reranker) | Second-stage precision — measured, not assumed |
| **Fusion** | Reciprocal Rank Fusion | Scale-free combination, one constant, no tuning knob |
| **Vector search** | NumPy matmul | 57k × 768 is 169 MB; exhaustive search is milliseconds and exact |
| **Generation & judging** | Anthropic Claude (`claude-opus-5`) | Structured outputs for mechanically parseable verdicts |
| **Cost control** | Message Batches API | 50% pricing on an evaluation nothing is waiting for |
| **Significance** | Paired bootstrap (NumPy) | 648 queries can't resolve every gap; this says which |
| **Dashboard** | Streamlit | Live retrieval + both benchmark tables |

Why no vector database: at 57,638 × 768 float32 the embedding matrix is
169 MB and an exhaustive cosine search takes milliseconds. FAISS or a hosted vector DB
would add a dependency, an index-build step, and an approximate-recall
tradeoff to solve a problem this corpus does not have. That decision would
flip at ~10M documents.

## 🚀 Setup

```bash
cd project-03-financial-rag
python -m venv venv && source venv/bin/activate
pip install -r requirements.txt
```

The FiQA dataset (a 17 MB download, 47 MB extracted) fetches itself on
first use — no manual step, no Kaggle account:

```bash
python -m src.data.loader
# corpus:  57,638 documents
# queries: 648 test queries with judgments
# qrels:   1,706 judged (query, doc) pairs -- 2.63 relevant docs per query
```

### Retrieval benchmark (no API key, no cost)

```bash
python -m src.evaluation.run_retrieval_eval     # ~20 min, mostly corpus embedding
python -m src.evaluation.significance
```

Corpus embeddings and ranked runs are cached under `data/processed/`, so
re-running scores in seconds. Individual stages: `--stages bm25 dense_bge`.

### Answer-quality evaluation (needs Anthropic credentials)

Set `ANTHROPIC_API_KEY` or run `ant auth login`. **Price the run before you
pay for it** — the pilot phase measures real token usage on a handful of
questions and extrapolates:

```bash
python -m src.evaluation.run_generation_eval --phase pilot --n 3
#   generation      600 requests   ~$  4.94
#   judging        1350 requests   ~$  8.95
#   cross-model     300 requests   ~$  0.40
#   TOTAL                          ~$ 14.29

python -m src.evaluation.run_generation_eval --phase generate
python -m src.evaluation.run_generation_eval --phase judge
python -m src.evaluation.run_generation_eval --phase analyze
```

Each phase persists its batch ids, so an interrupted poll resumes instead
of re-paying for work already submitted.

### Dashboard

```bash
streamlit run app.py
```

Or via Docker (the corpus and embeddings are mounted, not baked in):

```bash
docker build -t financial-rag .
docker run -p 8501:8501 \
  -e ANTHROPIC_API_KEY="$ANTHROPIC_API_KEY" \
  -v "$(pwd)/data:/app/data" \
  financial-rag
```

Without credentials the dashboard still serves live retrieval and both
benchmark tabs; only answer generation is disabled.

### Tests

```bash
pytest tests/ -q
```

## ⚠️ Limitations

Full writeup in [`MODEL_CARD.md`](MODEL_CARD.md). The short version:

- **One benchmark, one domain.** Every conclusion here is about English
  financial forum text. "Reranking hurts" is a finding about *this corpus*
  with *these rerankers*, not a general law.
- **The judge is a Claude model judging a Claude model.** Self-preference
  bias is a live risk; it is measured with a cross-model check rather than
  argued away.
- **The gold labels are incomplete.** FiQA's qrels mark 2.63 documents per
  question as relevant out of 57,638; unjudged documents count as
  non-relevant, which understates every retriever equally.
- **Not investment advice.** The corpus is anonymous forum opinion. The
  system retrieves and summarizes it; it does not verify it.
